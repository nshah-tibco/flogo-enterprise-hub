  • Branch / ATM locations & hours

  • Block a lost / stolen / compromised card

Out of scope (declined): loan approvals, investment/tax advice, opening/closing accounts, external wires.

Design principle

Why three separate apps?

MCP Server

Reads only

Stateless lookups, safe to retry. The LLM picks a tool by intent and filters the rows. No side effects — nothing can be broken by a read.

A2A Servers

Writes only

Each state-changing action is its own agent with its own guardrails, port, and deploy/scale lifecycle. Confirmed & bounded.

Orchestrator

The brain

WebSocket chat. Classifies intent, calls read tools or hands off to write agents, keeps session memory, enforces scope.

Separation of read vs. write is the core safety property: reads can’t mutate, writes are explicit, confirmed, and independently governable.

Orchestrator — intent routing & guardrails

Routing logic (system prompt)
  • Identify the customer by CUST-2026-NNNNN
  • Balance / cards / loans / branch → MCP tool
  • “Don’t recognize this charge” → dispute agent
  • “Lost / stolen card” → block-card agent
  • “Email me” → email agent (once, last)
Safety & behavior
  • Confirm before any write
  • Only reveal the requesting customer’s data
  • Session memory for multi-turn chat
  • Decline out-of-scope requests politely
  • Report partial results on failure

Flow: #wsserver → #agentactivity (MCP + 3 A2A wired in) → #wswritedata
